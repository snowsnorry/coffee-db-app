# Coffee DB Design

The product design system has not been defined yet. This repository intentionally ships a neutral, responsive status screen rather than establishing visual direction ahead of the dedicated UI tasks.

## Skeleton rules

- Keep the placeholder semantic, keyboard accessible and readable from 320 px upward.
- Use MUI for accessible UI primitives and Tailwind CSS for utility styling so both chosen technologies remain exercised.
- Do not treat the placeholder palette, typography or layout as a future product design contract.
- Do not add decorative assets, a marketing surface or invented catalogue interactions before product requirements are defined.

When product UI work begins, replace this document with the approved design direction and record the runtime design-token sources here.
